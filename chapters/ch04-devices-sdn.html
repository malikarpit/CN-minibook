Section 4.1

Repeater (Layer 1 Device)

As electrical or optical signals travel through a transmission cable, they experience resistance and energy dissipation, leading to attenuation (loss of signal strength) and waveform distortion. If a cable runs beyond its maximum physical specification (e.g., 100 meters for Cat5e copper twisted-pair), the signal becomes too weak and distorted for the receiving node to decode accurately. A Repeater solves this fundamental physical constraint.

Repeater (Regenerator)

A 2-port electronic device operating strictly at Layer 1 (Physical Layer) that receives an incoming attenuated, noisy, or distorted signal, cleans and reshapes it, regenerates it to its original voltage amplitude and timing, and retransmits it onto the next segment of the cable, effectively extending the physical geographical reach of the network.

Figure 4.1: Amplifier vs Regenerator (Repeater)
   INCOMING SIGNAL (Attenuated + Noisy):
   ---\_/\_---\_/\_---

   ANALOG AMPLIFIER:
   Increases amplitude of EVERYTHING, including the noise!
   ===/^\/^\===/^\/^\=== (Distortion is magnified)

   DIGITAL REPEATER (REGENERATOR):
   Samples signal, decides if bit is 0 or 1, and emits brand-new pristine square wave:
   ---+-----+---+-----+---
      |     |   |     |
   ---+     +---+     +--- (Zero noise carried forward!)
⚠️ Repeater vs Amplifier: The Vital Difference

An Amplifier simply boosts the overall amplitude of the electrical signal—meaning it amplifies both the intended data signal and whatever background noise was accumulated along the wire. A Repeater, by contrast, is a regenerator: it decodes the binary bits ($1$ or $0$), discards the noise completely, and constructs a brand new, crisp, noise-free copy of the waveform from scratch.

Characteristics and Limitations of Repeaters

  • Layer of Operation: Layer 1 (Physical Layer) exclusively.
  • No Address Awareness: Has no concept of MAC addresses, IP addresses, or packet boundaries. It processes individual electrical voltage levels/bits.
  • No Filtering: Does not filter bad frames, collisions, or broadcast storms. If garbage or a collision signal enters Port 1, it is faithfully regenerated and blasted out of Port 2.
  • Single Collision Domain: Devices on both sides of a repeater share the exact same collision domain.
  • The 5-4-3 Rule (Legacy Ethernet 10Base-5/10Base-2): In classic shared coaxial bus networks, you could have at most 5 segments, connected by 4 repeaters, with only 3 populated segments (segments with actual host computers attached) to prevent propagation delay from violating CSMA/CD collision detection timing.
Section 4.2

Hub (Multiport Repeater)

A Hub is simply a multiport repeater. Instead of having just two ports to connect two cable segments, a hub typically features 4, 8, 16, or 24 ports, serving as the central connection point in a physical star topology.

Hub (Multiport Repeater)

A non-intelligent Layer 1 hardware device with multiple ports. Whenever an electrical bit arrives at any one port, the hub automatically regenerates and broadcasts (floods) that bit out to every other connected port, regardless of who the intended recipient is.

Figure 4.2: Hub Operation — Blind Flooding to All Ports
                      +-------------------+
                      |      HUB (L1)     |
                      +-------------------+
                       /        |                              /         |                             Port 1    Port 2    Port 3
                    /           |                          [ Host A ]   [ Host B ]   [ Host C ]
             (Sends frame
              intended for B)
      
    1. Host A transmits frame for Host B.
    2. Hub blindly broadcasts the electrical signal to BOTH Host B AND Host C!
    3. Host B accepts the frame; Host C inspects MAC, sees mismatch, drops frame.

Types of Hubs

Hub Type Power Required? Functionality & Capabilities
Passive Hub No external power needed. Simply acts as a physical junction box. Connects wires directly without regenerating or cleaning signals. Relies entirely on the sender's signal strength. Maximum distance is cut in half.
Active Hub Yes (AC electrical power). Contains electronic circuitry that regenerates, cleans, and amplifies the signal before broadcasting it to all ports. True multiport repeater.
Intelligent (Managed) Hub Yes (Microprocessor onboard). Includes an onboard management processor that monitors port traffic, detects jabbering (malfunctioning) nodes, allows SNMP remote monitoring, and can shut down problematic ports administratively.
⚠️ Massive Drawbacks of Hubs: Why They Are Obsolete
  • Shared Bandwidth: In a 100 Mbps 8-port hub, the 100 Mbps bandwidth is shared among all 8 ports. If all nodes transmit, each gets only a fraction of the capacity.
  • Single Collision Domain: All ports belong to one giant collision domain. Only one device can transmit at a time. If Host A and Host C transmit simultaneously, a collision occurs!
  • Half-Duplex Only: Nodes cannot transmit and receive simultaneously.
  • Security Vulnerability: Any device running a network sniffer (like Wireshark) can capture all traffic on the entire hub.
Section 4.3

Bridge & Transparent Learning

To eliminate the crippling collision problems of hubs and repeaters, networking engineers developed the Bridge. A bridge operates at Layer 2 (Data Link Layer). It is smart enough to inspect the physical MAC addresses inside frames and make intelligent forwarding and filtering decisions.

Bridge (Layer 2 Device)

A 2-port or low-density multi-port device that inspects incoming frames at the Data Link Layer, maintains a MAC address forwarding database (Content Addressable Memory / CAM table), and separates a single large collision domain into two or more independent, smaller collision domains.

Figure 4.3: Bridge Isolating Collision Domains
   [ Segment 1: Collision Domain 1 ]          [ Segment 2: Collision Domain 2 ]
     [ Host A ]       [ Host B ]                 [ Host C ]       [ Host D ]
     (MAC: AA)        (MAC: BB)                  (MAC: CC)        (MAC: DD)
          \              /                            \              /
        --------------------                        --------------------
                 |                                           |
               Port 1                                      Port 2
              +---------------------------------------------+
              |              BRIDGE (Layer 2)               |
              |   CAM Table: [AA -> Port 1] [CC -> Port 2]  |
              +---------------------------------------------+

   • If Host A sends to Host B: Bridge reads Dest MAC (BB), sees it is on Port 1,
     and FILTERS (drops) the frame from crossing to Segment 2. Segment 2 remains silent!
   • If Host A sends to Host C: Bridge FORWARDS frame through Port 2 to Segment 2.

The Backward Learning Algorithm (Transparent Bridging)

How does a bridge know which computer is attached to which port without manual configuration? It uses the elegant Backward Learning (Self-Learning) algorithm:

Transparent Bridge Learning Rules

When a frame arrives at Port $P$ with Source MAC $= S$ and Destination MAC $= D$:
1. LEARN: Record the pair (Source MAC S, Port P, Timestamp) in the CAM table. If already present, refresh the aging timer.
2. DECIDE: Look up Destination MAC $D$ in the CAM table:
    • If $D$ is found on Port $P$ (same port it came from): FILTER (drop the frame; the recipient is on the same segment and has already heard it).
    • If $D$ is found on a DIFFERENT Port $Q$: FORWARD the frame out of Port $Q$ only.
    • If $D$ is NOT found (unknown destination) OR is a Broadcast address (`FF:FF:FF:FF:FF:FF`): FLOOD the frame out to ALL ports except the arrival port $P$.

Bridge Types

  • Transparent Bridge: The standard Ethernet bridge described above. Stations are completely unaware of its existence; it auto-learns and configures itself.
  • Source Routing Bridge (Token Ring): Used in IBM Token Ring networks. The sending station determines the entire route through bridges and includes the hop-by-hop bridge routing path inside the frame header.
Section 4.4

Switch & Switching Modes

A Switch is essentially a high-performance, high-density multiport bridge. While traditional bridges performed frame inspection and forwarding via software using a general-purpose CPU, a modern switch uses specialized hardware chips called ASICs (Application-Specific Integrated Circuits), enabling simultaneous wire-speed switching across dozens or hundreds of ports.

Layer 2 Switch (Hardware-Based Bridge)

A high-speed multi-port Layer 2 device where each individual port is its own dedicated collision domain. When operating in full-duplex mode with dedicated links to each host, collisions are 100% eliminated from the network!

Figure 4.4: Switch Architecture — Dedicated Collision Domains
                      +-----------------------------+
                      |       LAYER 2 SWITCH        |
                      |   Internal Switching Fabric |
                      +--[P1]----[P2]----[P3]----[P4]+
                          |        |       |       |
                       [Host A] [Host B] [Host C] [Host D]
                          
     Every port = 1 independent collision domain!
     Host A can talk to Host B at full 1 Gbps, WHILE SIMULTANEOUSLY
     Host C talks to Host D at full 1 Gbps through the internal fabric!

The Three Frame Switching Modes

Switches can process and forward frames using three distinct internal methods, offering different balances between latency and error detection:

Switching Method When Forwarding Begins Latency Error Checking? Forwards Corrupted Frames?
1. Store-and-Forward Waits until the entire frame (all bytes including the CRC trailer) is completely received and buffered. Highest latency (proportional to frame length). Full CRC check. Discards any frame with errors, invalid length, or bad FCS. Never. Only pristine, error-free frames are forwarded. (Default in modern switches).
2. Cut-Through (Fast-Forward) Immediately after reading the first 6 bytes (the Destination MAC address). Lowest possible latency (near instantaneous). Zero error checking. Forwarding begins before the CRC trailer has even arrived! Yes! Corrupted or collision-damaged runts are blindly forwarded onto other ports.
3. Fragment-Free (Modified Cut-Through) Waits until the first 64 bytes of the frame are received. Intermediate latency. Checks minimum Ethernet collision window (64 bytes). Filters out collision runts (< 64 bytes). Filters out collision fragments; may still forward checksum errors if corruption occurs after byte 64.
💡 Why 64 Bytes for Fragment-Free?

Under IEEE 802.3 Ethernet standards, any collision on the cable is guaranteed to occur within the first 512 bits (64 bytes) of transmission (the slot time). Frames shorter than 64 bytes resulting from collisions are called runts. Fragment-Free buffers the first 64 bytes to guarantee that no collision runt ever gets forwarded through the switch!

Section 4.5

Router & Routing Architecture

While hubs, bridges, and switches operate locally within a single broadcast domain (LAN), the Router is the foundational pillar of the global Internet. Operating at Layer 3 (Network Layer), a router connects multiple distinct, heterogeneous logical networks together.

Router (Layer 3 Device)

An intelligent networking device that inspects the Logical IP addresses in packet headers, maintains dynamic routing tables via routing protocols, and routes packets between distinct subnets, breaking both collision domains AND broadcast domains.

Figure 4.5: Router Connecting Two Heterogeneous Subnets
   [ LAN 1: 192.168.1.0/24 ]                       [ LAN 2: 10.0.0.0/8 ]
     (Broadcast Domain 1)                            (Broadcast Domain 2)
   [Host A]       [Host B]                         [Server C]     [Server D]
      \              /                                 \              /
    +------------------+                             +------------------+
    |  SWITCH 1 (L2)   |                             |  SWITCH 2 (L2)   |
    +------------------+                             +------------------+
             | (Port FastEth0/0: 192.168.1.1)                 | (Port FastEth0/1: 10.0.0.1)
             +--------------------+   ROUTER (L3)   +---------+
                                  |   Routing Table |
                                  +-----------------+

Core Responsibilities of a Router

  1. Separating Broadcast Domains: Routers do not forward Layer 2 or Layer 3 broadcast packets by default. If Host A sends a broadcast frame (`FF:FF:FF:FF:FF:FF`), Switch 1 floods it across LAN 1, but Router FastEth0/0 drops it! LAN 2 never sees the broadcast.
  2. Path Determination (Routing): Evaluates multiple paths across intermediate networks using algorithms (Dijkstra's SPF, Bellman-Ford) and routing protocols (OSPF, RIP, BGP) to select the optimal path based on metrics (hop count, bandwidth, delay).
  3. Packet Forwarding: Reads the destination IP, matches it against its routing table using Longest Prefix Match (LPM), rewrites the Layer 2 MAC frame header, and sends the packet out the designated outgoing interface.
  4. Protocol Conversion / Heterogeneous Interconnection: Can interconnect totally different physical and data-link technologies (e.g., receiving an Ethernet 802.3 frame, stripping the MAC header, and encapsulating the IP packet into a WAN PPP or HDLC frame).
Section 4.6

Gateway & Protocol Translators

In classical computer networking theory, a Gateway (often called a Protocol Translator or Application Gateway) is the most sophisticated internetworking device. It operates at all layers (Layers 1 through 7) of the OSI model.

Gateway (Protocol Converter / L1–L7)

A system capable of translating completely incompatible communication protocols, data formats, and architectural semantics across all layers of the OSI stack, allowing radically different networks (e.g., an IBM SNA mainframe network and an IP/TCP network) to communicate.

⚠️ Gateway: Formal Definition vs "Default Gateway"

Do not confuse the two uses of the word Gateway:

  • Formal OSI Gateway: A full protocol translator operating up to Layer 7 (e.g., an Email Gateway converting Microsoft Exchange MAPI messages to standard Internet SMTP, or a VoIP Gateway converting analog voice PSTN signals to SIP/RTP IP packets).
  • Everyday "Default Gateway" in PC Settings: In modern IP configuration, "Default Gateway" is simply the local IP address of your Router (e.g., 192.168.1.1), which hosts use as their exit door to reach remote subnets.
Section 4.7

Modem (Modulator / Demodulator)

Computers process and store information as digital discrete binary signals ($0 ext{s}$ and $1 ext{s}$). However, traditional telecommunication channels—such as legacy copper telephone local loops, cable TV coaxial systems, and wireless radio atmospheric links—were engineered to carry continuous analog waveforms. A Modem bridges this gap.

Modem (MOdulator - DEModulator)

A hardware device that converts outgoing digital computer data into analog signals by modulating a carrier frequency (Modulation), and converts incoming analog signals back into discrete digital binary data (Demodulation).

Figure 4.6: Modulation and Demodulation Across an Analog Channel
   [ COMPUTER A ]                  [ MODEM A ]                         [ MODEM B ]                  [ COMPUTER B ]
   Digital Bits:                   MODULATION:                         DEMODULATION:                Digital Bits:
   0 1 0 1 1 0                     Digital -> Analog                   Analog -> Digital            0 1 0 1 1 0
   [==_==__==_] ===== (RS-232) ==> ~~~~~~~~~~~~~~ === (Analog Line) => ~~~~~~~~~~~~~~ ==> (RS-232) [==_==__==_]

Modem Variations in Modern Networks

  • Dial-Up Modem (PSTN): Modulated audio-frequency tones over the 4 kHz voice-band telephone network, topping out at 56 kbps (V.90/V.92 standard).
  • DSL Modem (Digital Subscriber Line): Transmits high-frequency digital data over existing copper telephone wires without interfering with voice frequencies (ADSL, VDSL).
  • Cable Modem: Uses coaxial television cable channels conforming to DOCSIS (Data Over Cable Service Interface Specification) standards.
  • Optical Network Terminal (ONT / "Fiber Modem"): Converts incoming light pulses from fiber-optic GPON/EPON lines into standard electrical Ethernet frames.
Section 4.8

Wireless Access Point (AP)

A Wireless Access Point (WAP or AP) acts as a Layer 2 wireless bridge. It allows wireless devices (smartphones, laptops, IoT gadgets) conforming to IEEE 802.11 standards to connect seamlessly into a wired IEEE 802.3 Ethernet LAN infrastructure.

Access Point (Layer 2 Wireless Bridge)

A device operating at Layer 2 that converts IEEE 802.11 Wi-Fi radio frequency frames into IEEE 802.3 Ethernet wired frames, broadcasting a Service Set Identifier (SSID) and arbitrating wireless channel access via CSMA/CA.

📌 What is a "Home Wi-Fi Router"?

The plastic box from your ISP sitting in your living room is actually a multi-device combo unit integrating 4 distinct devices inside a single chassis:
1. A Wireless Access Point (for Wi-Fi connectivity)
2. A 4-port Layer 2 Switch (for wired Ethernet ports)
3. A Layer 3 Router (with NAT and DHCP server for connecting LAN to WAN)
4. A Modem / ONT (DSL/Cable/Fiber interface connecting to the street)

Section 4.9

Firewall & Security Filtering

A Firewall is a specialized security mechanism (hardware appliance or software program) that monitors, inspects, and filters incoming and outgoing network traffic based on an organization's predetermined security rules. It forms the primary protective perimeter between a trusted internal network and an untrusted external network (such as the public Internet).

Generations of Firewalls

Firewall Type OSI Layer Inspection Mechanism Pros & Cons
Stateless Packet Filter Layer 3 & 4 Inspects each packet in isolation against static rules (Source IP, Dest IP, Source Port, Dest Port, Protocol). Extremely fast, low CPU usage. But vulnerable to IP spoofing and cannot track connection states.
Stateful Inspection (SPI) Layer 3, 4 (State Table) Maintains a dynamic state table tracking active TCP connections (SYN, ESTABLISHED, FIN). Only permits inbound packets if they belong to an existing session initiated from inside. Standard modern firewall. High security with good throughput. Prevents unsolicited inbound probes.
Application Layer (Proxy) Layer 7 Acts as an intermediary; terminates connection, reconstructs and parses application payloads (HTTP headers, SQL commands, virus signatures). Highest security inspection; can block specific URLs or malicious payloads. High CPU/latency overhead.

Section 4.11

Collision Domains vs Broadcast Domains (With Calculations)

Calculating the exact number of Collision Domains and Broadcast Domains in an arbitrary network diagram is one of the highest-frequency numerical questions in university exams, GATE, and Cisco CCNA certifications.

1. Collision Domain

A physical network segment or set of shared links where simultaneous packet transmissions by two or more devices will collide with one another.
• Rule 1: A Hub or Repeater does NOT divide collision domains. All ports on a hub belong to 1 single collision domain.
• Rule 2: A Bridge, Switch, or Router separates collision domains. Every single active port on a switch/router is 1 distinct collision domain.

2. Broadcast Domain

The logical boundary of a network within which any broadcast frame (`FF:FF:FF:FF:FF:FF` or IP `255.255.255.255`) transmitted by any node will be forwarded to and heard by all other nodes.
• Rule 1: Hubs, Repeaters, Bridges, and standard Layer 2 Switches do NOT separate broadcast domains. They forward broadcasts to all ports.
• Rule 2: Routers break broadcast domains. Each active interface of a router defines the boundary of 1 distinct broadcast domain (unless VLANs are configured).

Master Counting Rules Cheat Sheet

   DEVICE             COLLISION DOMAINS CREATED           BROADCAST DOMAINS CREATED
   ---------------------------------------------------------------------------------
   Hub (N ports)      1 (All N ports share 1 domain)      1 (Shares same broadcast domain)
   Bridge (2 ports)   2 (Each port is 1 domain)           1 (Broadcasts pass through)
   Switch (N ports)   N (Each active port is 1 domain)    1 (Default: 1 broadcast domain)
   Router (M ports)   M (Each active port is 1 domain)    M (Each port is a NEW broadcast domain!)

Worked Example: Comprehensive Domain Counting Problem

Figure 4.7: Practice Network Topology for Domain Counting
      [PC 1]   [PC 2]                 [PC 3]   [PC 4]
        \       /                       \       /
       +---------+                     +---------+
       |  HUB 1  |                     |  HUB 2  |
       +---------+                     +---------+
            |                               |
          Port 1                          Port 2
         +---------------------------------------+
         |             SWITCH 1 (L2)             |
         +---------------------------------------+
                            | Port 3
                            |
                     (Interface e0)
                   +-----------------+
                   |   ROUTER (L3)   |
                   +-----------------+
                     (Interface e1)
                            |
                            | Port 1
         +---------------------------------------+
         |             SWITCH 2 (L2)             |
         +---------------------------------------+
            |               |               |
          Port 2          Port 3          Port 4
            |               |               |
         [PC 5]          [PC 6]          [PC 7]
📝 Step-by-Step Solution

1. Count Broadcast Domains:
Look at the Router. The router has 2 active interfaces: e0 (left side) and e1 (right side).
Routers block broadcasts. Therefore, everything connected to interface e0 forms Broadcast Domain 1, and everything connected to interface e1 forms Broadcast Domain 2.
👉 Total Broadcast Domains = 2

2. Count Collision Domains:
Let's count link by link:
• Left Side (Switch 1 & Hubs):
  - Port 1 of Switch 1 connects to Hub 1. Hub 1 and [PC 1, PC 2] form 1 collision domain.
  - Port 2 of Switch 1 connects to Hub 2. Hub 2 and [PC 3, PC 4] form 1 collision domain.
  - Port 3 of Switch 1 connects to Router e0: forms 1 collision domain.
  (Subtotal left side = 3 collision domains).
• Right Side (Switch 2 & PCs):
  - Port 1 of Switch 2 connects to Router e1: 1 collision domain.
  - Port 2 of Switch 2 connects to PC 5: 1 collision domain.
  - Port 3 of Switch 2 connects to PC 6: 1 collision domain.
  - Port 4 of Switch 2 connects to PC 7: 1 collision domain.
  (Subtotal right side = 4 collision domains).
👉 Total Collision Domains = 3 + 4 = 7 Collision Domains

Section 4.12

Introduction to Software-Defined Networking (SDN) 🎓 Uni: Introduction to SDN 🎓 Uni Syllabus

For four decades, computer networking followed a rigid, decentralized model: every router and switch purchased from vendors (such as Cisco, Juniper, or Arista) contained its own proprietary operating system and made its own independent forwarding and routing decisions.

The Limitations of Traditional Networking

  • Tightly Coupled Planes: In every traditional box, the decision-making brain (Control Plane) and the packet-forwarding hardware (Data Plane) are fused together inside the same physical chassis.
  • Complex Distributed Configuration: Changing a network policy across an enterprise requires engineers to log into hundreds or thousands of routers individually via CLI (`ssh`) and manually configure them. One typo can take down an entire datacenter.
  • Slow Innovation & Vendor Lock-in: New routing protocols take 5 to 10 years to be standardized by the IETF and implemented by hardware vendors in firmware.
Software-Defined Networking (SDN) Paradigm

An architectural framework that decouples the network control plane (decision making) from the underlying data plane (packet forwarding), centralizing network intelligence and control in a software-based Controller that manages distributed physical/virtual forwarding switches via standardized open APIs.

Figure 4.8: Traditional Decentralized Routing vs SDN Centralized Control
   TRADITIONAL NETWORKING:                            SOFTWARE-DEFINED NETWORKING (SDN):
   (Control & Data fused in every box)                 (Centralized Brain, Dumb Fast Forwarders)

      +-------------+     +-------------+                    +-----------------------------+
      | CONTROL PL. |     | CONTROL PL. |                    |   SDN CONTROLLER (Brain)    |
      |  (OSPF/BGP) |     |  (OSPF/BGP) |                    |  Global Network Map & Logic |
      +-------------+     +-------------+                    +-----------------------------+
             |                   |                                     ↕ (OpenFlow API)
      +-------------+     +-------------+                    +---------+---------+---------+
      | DATA PLANE  |<===>| DATA PLANE  |                    | Switch1 | Switch2 | Switch3 |
      | (Forwarding)|     | (Forwarding)|                    | Forward | Forward | Forward |
      +-------------+     +-------------+                    +---------+---------+---------+
         Router A            Router B                          (Pure Data Plane Hardware)
Section 4.13

SDN Three-Tier Architecture & OpenFlow Protocol

The standard SDN architecture defined by the Open Networking Foundation (ONF) is organized into three distinct hierarchical planes connected by open interfaces:

Figure 4.9: The Three-Tier SDN Architectural Model
   +-----------------------------------------------------------------+
   | 1. APPLICATION PLANE                                            |
   |    Network Monitoring, Security/Firewall Apps, Traffic Eng, QoS |
   +-----------------------------------------------------------------+
                                ↕
        NORTHBOUND APIs (RESTful APIs, Java/Python SDKs)
                                ↕
   +-----------------------------------------------------------------+
   | 2. CONTROL PLANE (The Network Brain)                            |
   |    SDN Controllers (ONOS, OpenDaylight, Floodlight, Ryu)         |
   |    Maintains global network topology, calculates flow rules     |
   +-----------------------------------------------------------------+
                                ↕
        SOUTHBOUND APIs (OpenFlow Protocol, NETCONF, P4)
                                ↕
   +-----------------------------------------------------------------+
   | 3. DATA / INFRASTRUCTURE PLANE                                  |
   |    White-box Switches, Virtual Switches (OVS), Routers          |
   |    Pure fast packet forwarding based on Flow Tables             |
   +-----------------------------------------------------------------+

The Planes and Interfaces Explained

Tier / Interface Location & Nature Primary Function & Examples
Application Plane Top Tier Network applications that define policies (e.g., dynamic firewall rules, load balancers, energy managers, path optimizers). Communicates policy intent downward.
Northbound API Upper Boundary Interfaces between Applications and the Controller. Typically software REST APIs, JSON-RPC, or Python APIs. Not yet fully standardized by a single body.
Control Plane (Controller) Middle Tier The Network Operating System. Has a unified, real-time bird's-eye view of the entire global network topology. Converts high-level application policies into concrete low-level flow rules and pushes them to switches. Examples: OpenDaylight, ONOS, Ryu, Floodlight.
Southbound API (OpenFlow) Lower Boundary Standardized protocol through which the Controller communicates with physical or virtual switches. OpenFlow is the industry standard southbound protocol.
Data Plane (Infrastructure) Bottom Tier Collection of high-speed forwarding elements (hardware ASIC switches, Open vSwitch). Possesses no routing intelligence; simply matches incoming packet headers against flow tables and executes instructions.

Inside an OpenFlow Switch: The Flow Table

In an OpenFlow-enabled switch, traditional separate MAC address tables, IP routing tables, and ACL lists are unified into a single generalized construct called a Flow Table. Each flow table entry consists of three mandatory components:

Structure of an OpenFlow Flow Entry

[ MATCH FIELDS ] | [ COUNTERS ] | [ ACTIONS / INSTRUCTIONS ]

• Match Fields: Inspects up to 12 distinct packet header fields across Layers 1, 2, 3, and 4 (Ingress Port, Source/Dest MAC, VLAN ID, Source/Dest IP, IP Protocol, Source/Dest TCP/UDP Port).
• Counters: Tracks statistics for each flow (Received packets, Received bytes, Flow duration). Used for billing, QoS, and DDoS detection.
• Actions: Dictates what the switch must do when a match occurs:
  - FORWARD: Send packet out a specified port (or flood out all ports).
  - DROP: Silently discard the packet (acting as a firewall).
  - MODIFY FIELD: Rewrite header fields (e.g., modifying IP/Port for NAT).
  - SEND TO CONTROLLER (Packet-In): Forwards unknown packets to the SDN Controller for decision making!

Section 4.14

Chapter Summary & High-Yield Exam Traps

⚡ High-Yield Rapid Review Points
  • Repeater: Layer 1. Cleans and regenerates electrical/optical signals; extends maximum distance. Does NOT filter.
  • Hub: Layer 1 multiport repeater. Blindly floods incoming bits out all other ports. Creates 1 collision domain and 1 broadcast domain.
  • Bridge: Layer 2 software device. Maintains CAM table; breaks network into multiple collision domains. Passes broadcasts.
  • Switch: Layer 2 multiport bridge with ASIC hardware. Every port = 1 collision domain. Eliminates collisions in full duplex.
  • Switching Modes: Store-and-Forward (checks full CRC), Cut-Through (reads first 6 bytes, fast), Fragment-Free (reads first 64 bytes to eliminate collision runts).
  • Router: Layer 3 intelligent device. Breaks both collision domains AND broadcast domains. Forwards based on destination IP.
  • Gateway: Layers 1–7 protocol converter. Connects incompatible network architectures.
  • Modem: Modulator-Demodulator. Converts digital binary bits to analog carrier waveforms and vice-versa.
  • Domain Rules:
    • Total Collision Domains = (Sum of all active switch ports + router ports connecting to switches/devices; hubs count as 1 for all their ports).
    • Total Broadcast Domains = Total active router interfaces.
  • SDN: Decouples Control Plane (Controller) from Data Plane (Switches). Northbound API connects to Apps; Southbound API (OpenFlow) connects to Switches.

Top 5 High-Yield Traps in Exams

Trap # The Common Misconception The Technical Reality
Trap 1 "Adding a switch breaks a broadcast domain into smaller pieces." False! Switches only separate collision domains. All ports on a standard switch belong to one single broadcast domain. Only routers (or VLANs) break broadcast domains.
Trap 2 "Cut-Through switching drops corrupted frames." False! Cut-Through forwards after reading just the first 6 bytes (destination MAC). The CRC checksum is at the end of the frame, so Cut-Through blindly forwards corrupted frames!
Trap 3 "Hubs and switches have the same performance in full-duplex mode." False! Hubs cannot operate in full-duplex at all because all ports share a single electrical broadcast bus. Only switches support full-duplex.
Trap 4 "OpenFlow is an SDN Controller." False! OpenFlow is a Southbound communication protocol / API. The Controller is software like ONOS, OpenDaylight, or Ryu that uses OpenFlow to talk to switches.
Trap 5 "A bridge learns port locations from the Destination MAC address." False! Bridges learn by inspecting the SOURCE MAC address of incoming frames. The destination MAC is used solely for the forwarding decision.
