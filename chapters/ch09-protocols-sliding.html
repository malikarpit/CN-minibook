9.1 Why Data Link Control Protocols Are Required

🎓 Uni Required Prescribed syllabus topic: Data Link Layer: Elementary Data Link Protocols (Flow & Error Control Need)
Data Link Protocol — First-Principles Definition

A Data Link Control Protocol is a formal set of operational rules and message exchange specifications that govern communication between two directly connected physical nodes. Its primary objective is to manage the transmission rate (Flow Control) and guarantee data delivery across an inherently imperfect transmission medium (Error Control).

1. The Physical Realities Demanding Protocols

In idealized mathematical network models, one node simply sends bits and another receives them. In reality, physical transmission lines and hardware endpoints impose three unforgiving engineering constraints:

  • Finite Receiver Memory & Processing Speed: A receiver machine is not an infinite data sink. It possesses limited RAM buffers and must spend CPU cycles decoding frames, calculating checksums, and pushing packets to the network layer. If a high-speed sender blasts frames faster than the receiver can consume them, receiver buffers overflow, leading to silent packet drops. Flow control is the mechanism that prevents a fast sender from swamping a slow receiver.
  • Channel Noise & Packet Distortion: Thermal noise, electromagnetic interference (EMI), attenuation, and lightning surges corrupt bits in transit. Furthermore, intermediate repeaters or switches may drop corrupted frames entirely. Without Error Control (detection and retransmission), higher-layer applications receive corrupted garbage or stalled streams.
  • Propagation Latency ($T_p$): Electromagnetic signals do not travel instantaneously; their velocity in copper or fiber is approximately $2 \times 10^8\text{ m/s}$ (two-thirds light speed). A transmission sent across a transatlantic fiber or a satellite link takes tens to hundreds of milliseconds to arrive. Protocols must account for this transit delay when coordinating state.

2. Flow Control vs. Error Control: Distinct Responsibilities

Attribute Flow Control Error Control
Primary Threat Fast sender overwhelming a slow receiver's memory buffer. Physical channel corruption, lost frames, or duplicated frames.
Triggering Condition Processing mismatch or queue exhaustion at receiver. Thermal noise, physical interference, or timer timeouts.
Core Mechanism Stop-and-Wait pacing, credit/sliding windows, pause frames. Cyclic Redundancy Checks (CRC), Timers, Acknowledgments, ARQ retransmissions.

Automatic Repeat reQuest (ARQ)

ARQ is an error-control strategy where the receiver sends explicit feedback messages—Acknowledgments (ACKs) or Negative Acknowledgments (NAKs)—back to the sender. If an ACK fails to arrive before the sender's retransmission countdown timer expires, the sender automatically retransmits the unacknowledged frame.

Important Invariants & Architectural Boundaries

  • Hop-by-Hop vs. End-to-End: Data link protocols operate strictly hop-by-hop between adjacent nodes (e.g., Host to Switch, Switch to Router). Transport Layer protocols (like TCP) duplicate flow and error control on an end-to-end basis across the entire Internet.
  • Feedback Requirement: Reliable transmission over an unreliable channel fundamentally requires a reverse feedback channel so the sender learns the fate of transmitted frames.
⚠️ Common Student Confusion: Flow Control vs Congestion Control

Do not confuse Flow Control with Congestion Control! Flow control is a point-to-point agreement between one sender and one receiver to prevent receiver buffer overflow. Congestion control is a system-wide mechanism preventing all network senders collectively from overloading intermediate routers and network switches in the core of the subnet.

⚡ Exam & GATE Insight

Whenever an exam question mentions "receiver buffer size = 0" or "receiver processing rate is slower than line transmission rate", the question is testing Flow Control. When it mentions "noisy channel" or "bit error rate $P_e > 0$", it is testing Error Control and ARQ.

9.2 Protocol 1: Unrestricted Simplex Protocol ("Utopia")

🎓 Uni Required Prescribed syllabus topic: Elementary Data Link Protocols: Protocol 1 (Unrestricted Simplex / Utopia)
Protocol 1 (Unrestricted Simplex / Utopia) — Definition

The Unrestricted Simplex Protocol is an idealized baseline data link protocol that assumes: (1) Data transmission is strictly unidirectional (simplex); (2) The physical transmission channel is completely noiseless, never losing or corrupting bits; and (3) The receiver possesses infinite processing speed and infinite buffer capacity.

1. Why This Protocol Exists in Curriculum

Computer science pedagogies begin with Utopia to isolate the fundamental algorithmic mechanics of framing before adding layers of complexity to counter noise and memory limitations. It demonstrates the simplest possible sender-receiver loop without any protocol overhead.

2. Algorithmic State Machine

Figure 9.2: Algorithmic Architecture of Utopia Protocol
   SENDER MACHINE                               RECEIVER MACHINE
+-------------------------------+             +-------------------------------+
| while (true) {                |             | while (true) {                |
|   wait_for_event();           |             |   wait_for_event();           |
|   from_network_layer(&packet);|             |   from_physical_layer(&frame);|
|   frame.data = packet;        | ======>     |   to_network_layer(&frame.data);
|   to_physical_layer(&frame);  |  (Continuous| }                             |
| }                             |   Blast)    +-------------------------------+
+-------------------------------+

3. Step-by-Step Operation

  1. The sender sits in an infinite loop waiting for data from its local network layer.
  2. Upon receiving a packet, the sender encapsulates it into a frame header and footer.
  3. The sender immediately passes the frame to the physical layer hardware for transmission.
  4. The receiver's physical layer captures the incoming bits and delivers the frame to the DLL.
  5. The receiver extracts the payload data and passes it up to its network layer.
  6. Neither sequence numbers, checksum calculations, acknowledgments, nor timers are used.

4. Mathematical Utilization

Because the sender never pauses to wait for feedback, transmission is uninterrupted:

Link Utilization of Utopia
\eta = \frac{T_t}{T_t} = 1.0 = 100\%
• $T_t$: Transmission time of frame.
• Utilization is mathematically maximal, but physically unachievable.

5. Why Utopia Fails in the Real World

  • Catastrophic Receiver Buffer Overflow: In reality, CPU interrupts, memory copy speeds, and higher-layer processing are finite. A sender running at 1 Gbps transmitting to a host running a slow disk write will cause the receiver's ring buffer to overflow in milliseconds, dropping virtually 100% of subsequent frames.
  • Zero Error Recovery: A single electromagnetic pulse flipping one bit renders frames invalid with no mechanism to request retransmission.
  • Unidirectional Only: No feedback channel exists for the receiver to communicate state back to the sender.
⚠️ Exam Trap: Does Utopia Have Flow Control?

NO. Students frequently write that Utopia uses "implicit flow control." Utopia has zero flow control and zero error control. It relies entirely on the impossible assumption that the receiver has infinite speed and infinite memory.

9.3 Protocol 2: Simplex Stop-and-Wait Protocol (Noiseless)

🎓 Uni Required Prescribed syllabus topic: Elementary Data Link Protocols: Protocol 2 (Simplex Stop-and-Wait Protocol)
Simplex Stop-and-Wait Protocol — First-Principles Definition

The Simplex Stop-and-Wait Protocol provides pure flow control over an error-free (noiseless) communication channel. The sender transmits exactly one data frame and then completely halts (stops) until it receives a feedback confirmation frame (acknowledgment, or ACK) from the receiver indicating that the previous frame was successfully processed.

1. Why This Protocol Was Developed

To eliminate the catastrophic receiver buffer overflow of Utopia without adding the complexity of error handling. By forcing the sender to wait for the receiver's explicit permission before sending the next frame, hardware buffers can never be overrun, even if the sender is 10,000 times faster than the receiver.

2. How the Feedback Loop Works

Figure 9.3: Stop-and-Wait Handshake Sequence on Noiseless Channel
       SENDER HOST                                         RECEIVER HOST
            |                                                   |
            | === [Data Frame 1] =============================> | (Extracts data,
            |                                                   |  passes to L3,
            |                  (Sender Pauses & Waits)          |  buffer freed)
            |                                                   |
            | <== [Dummy Acknowledgment (ACK)] =============== | (Sends ACK)
            |                                                   |
   (ACK Arrives! Sender                                         |
    fetches next packet)                                        |
            |                                                   |
            | === [Data Frame 2] =============================> | (Processes Frame 2)
            | <== [ACK] ======================================= |
            v                                                   v

3. Detailed Step-by-Step Execution

  1. Sender: Fetches packet from network layer, builds frame, and pushes it to the physical wire.
  2. Sender State: Sender enters a blocking wait state. It cannot fetch the next packet from the network layer until an ACK frame arrives.
  3. Receiver: Physical layer receives the frame. Data Link Layer delivers packet to network layer.
  4. Receiver Feedback: Once the network layer finishes consuming the packet, the receiver generates a tiny, special dummy control frame called an ACK and transmits it back across the reverse link.
  5. Cycle Repeat: The sender consumes the ACK, exits its waiting state, and repeats the process for Frame 2.

4. Invariants & Assumptions

  • Channel is Noiseless: Frames are never corrupted and never lost in transit.
  • Half-Duplex Capability: Data frames flow from sender to receiver; ACK frames flow in the reverse direction.
  • No Sequence Numbers Needed: Because frames cannot be lost or duplicated on a noiseless wire, sequence numbers are redundant in Protocol 2.

5. Fatal Flaw on Real Channels

💥 The Deadlock Vulnerability on Noisy Channels

If Protocol 2 is deployed on a real-world physical wire with noise, a catastrophic Deadlock occurs upon the first dropped transmission:

  • If Data Frame 1 is lost: The receiver never sees it, so it never sends an ACK. The sender waits for the ACK forever. Total system freeze!
  • If the ACK is lost: The receiver has delivered the packet and is waiting for Frame 2. The sender is waiting for the ACK. Neither side will ever transmit another bit!

Conclusion: Pure flow control is insufficient for real networks; protocols require retransmission timers and sequence numbering.

⚡ Exam & GATE Distinction

University exams frequently ask: "Why are sequence numbers NOT required in Protocol 2 (Simplex Stop-and-Wait)?"
Answer: Because Protocol 2 strictly assumes a noiseless channel. Frames can never be damaged or lost; therefore, retransmissions never occur, making duplicate frame detection unnecessary.

9.4 Protocol 3: Stop-and-Wait ARQ Protocol (Noisy Channels)

🎓 Uni Required Prescribed syllabus topic: Elementary Data Link Protocols: Protocol 3 (Stop-and-Wait ARQ Protocol)
Stop-and-Wait ARQ (Alternating Bit Protocol) — Definition

Stop-and-Wait Automatic Repeat reQuest (ARQ) is a data link layer protocol that provides both flow control and error control across an imperfect, noisy channel. It introduces three core recovery mechanisms: (1) A Retransmission Countdown Timer at the sender, (2) 1-bit Sequence Numbers ($0$ and $1$) on data frames, and (3) Sequence-numbered Acknowledgments (ACK 0 and ACK 1).

1. Why Stop-and-Wait ARQ Exists

Real-world physical channels corrupt bits and drop frames. Stop-and-Wait ARQ overcomes the deadlock vulnerability of Protocol 2 by guaranteeing that if an acknowledgment is not received within a deterministic window of time, the sender automatically re-sends the frame, while sequence numbering prevents the receiver from accepting duplicate copies.

2. The Three Architectural Pillars of Stop-and-Wait ARQ

  • 1. Retransmission Timer (Timeout): Whenever the sender transmits a frame, it starts a dedicated countdown timer. If a valid ACK arrives before the timer expires, the timer is stopped. If the timer expires before the ACK arrives (a timeout event), the sender retransmits the exact same frame and resets the timer.
  • 2. 1-Bit Sequence Numbers ($S_n \in \{0, 1\}$): Every transmitted frame carries a single sequence bit in its header, alternating between $0$ and $1$. Because only one frame is outstanding at any time, a 1-bit sequence space is mathematically sufficient to distinguish a new frame from a duplicate.
  • 3. Sequence-Numbered Acknowledgments ($R_n \in \{0, 1\}$): The receiver includes the sequence number of the next frame it expects in the ACK frame (or the frame just received, depending on convention). In the standard Tanenbaum/Kurose model, ACK 1 means: "I have successfully accepted Frame 0, and I am now waiting for Frame 1."
Figure 9.4: The Alternating-Bit State Transition
   Sender State Machine:
   [ Ready to Send 0 ] --- Transmit Frame 0 ---> [ Waiting for ACK 1 ]
          ^                                              |
          | Recv ACK 0                                   | Recv ACK 1
          | (Ignore/Retransmit)                          v
   [ Waiting for ACK 0 ] <--- Transmit Frame 1 --- [ Ready to Send 1 ]

3. Step-by-Step Normal Operation

  1. Sender transmits Frame 0, stores a copy in its buffer, and starts the timer.
  2. Receiver receives Frame 0, verifies CRC checksum. It matches expected sequence ($0$).
  3. Receiver delivers packet to Layer 3, increments expected sequence to $1$, and sends ACK 1.
  4. Sender receives ACK 1, cancels timer, and discards buffered Frame 0.
  5. Sender fetches next packet, transmits Frame 1, buffers it, and starts timer.
  6. Receiver accepts Frame 1, updates expected sequence to $0$, and returns ACK 0.
💡 Why is 1-Bit (Modulo-2) Sequence Space Sufficient?

Because the sender never transmits Frame $N+1$ until Frame $N$ is acknowledged, there is never more than one unacknowledged frame in transit. The only possible ambiguity is between the current frame and its immediate predecessor. A 1-bit sequence number ($0$ and $1$) provides the exact two distinct states needed to resolve this ambiguity completely.

9.5 Stop-and-Wait ARQ Failure Scenarios Walkthrough

🎓 Uni Required Prescribed syllabus topic: Elementary Data Link Protocols: Stop-and-Wait ARQ Failure Scenarios (Lost Frame, Lost ACK, Delayed ACK)
Protocol Failure Scenarios — First-Principles Definition

In real-world networks, three distinct physical failure conditions occur: (1) Frame Loss, where data never reaches the receiver; (2) ACK Loss, where the receiver accepts data but the confirmation is destroyed; and (3) Premature Timeout / Delayed ACK, where an ACK arrives after the sender's timer has already expired.

Scenario A: Lost Data Frame

A noise burst on the link flips bits, causing the receiver to reject the frame via CRC, or physical loss drops the frame entirely.

⚠️ Deep Technical Nuance: The Ambiguity of ACK Sequence Numbers

Why must ACK frames carry a sequence number? If ACKs were unnumbered (just a bare "ACK"), consider Scenario C: Sender transmits Frame 0, times out, retransmits Frame 0, and then transmits Frame 1. When a bare "ACK" arrives, the sender cannot tell whether it confirms Frame 0 or Frame 1! Labeling ACKs with ACK 0 and ACK 1 completely removes this ambiguity.

9.6 Performance Bottleneck of Stop-and-Wait & Efficiency

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols Need: Performance Limitations of Stop-and-Wait
Link Utilization ($\eta$ or $U$) — Definition

Channel Utilization ($\eta$), or efficiency, is the fraction of total operational time during which the physical transmission channel is actively carrying useful data bits, compared to the total time elapsed between successive transmissions.

1. First-Principles Mathematical Derivation of $\eta$

Let:

  • $L$ = Length of data frame (bits)
  • $B$ = Bandwidth / transmission rate of link (bits per second, bps)
  • $d$ = Physical distance between sender and receiver (meters)
  • $v$ = Propagation speed of signal in medium ($\approx 2 \times 10^8\text{ m/s}$ in copper/fiber)
  • $T_t$ = Transmission time of data frame $= \frac{L}{B}$ (seconds)
  • $T_p$ = Propagation delay across medium $= \frac{d}{v}$ (seconds)
  • $T_{\text{ack}}$ = Transmission time of small ACK frame $\approx 0$ (negligible)
  • $T_{\text{proc}}$ = Processing delay at nodes $\approx 0$

In Stop-and-Wait, the total cycle time ($T_{\text{total}}$) required to send one frame and receive its ACK is:

Total Cycle Time of Stop-and-Wait
T_{\text{total}} = T_t + T_p + T_{\text{proc}} + T_{\text{ack}} + T_p \approx T_t + 2T_p
\text{Round Trip Time (RTT)} = 2T_p

The channel is only actively used for transmission during time $T_t$. Therefore, link utilization is:

The Fundamental Stop-and-Wait Efficiency Formula
\eta = \frac{T_t}{T_t + 2T_p} = \frac{1}{1 + 2\left(\frac{T_p}{T_t}\right)} = \frac{1}{1 + 2a}
• $a = \frac{T_p}{T_t} = \frac{\text{Propagation Delay}}{\text{Transmission Time}}$ is the dimensionless delay-bandwidth ratio.
• Effective Throughput $= \eta \times B = \frac{L}{T_t + 2T_p}$ bps.

2. Worked Numerical Example: The Satellite Link Nightmare

📝 Worked Numerical 9.1 — Geostationary Satellite Link

Problem: A ground station transmits 1000-byte frames across a 1 Gbps geostationary satellite link at an altitude of $36,000\text{ km}$. Signal propagation speed $v = 3 \times 10^8\text{ m/s}$. Find parameter $a$, link utilization $\eta$, and effective throughput under Stop-and-Wait.

Solution:

  1. Frame size in bits: $L = 1000 \times 8 = 8000\text{ bits}$.
  2. Transmission time: $T_t = \frac{L}{B} = \frac{8000\text{ bits}}{10^9\text{ bps}} = 8 \times 10^{-6}\text{ s} = 8\ \mu\text{s}$.
  3. Propagation delay: $T_p = \frac{d}{v} = \frac{36 \times 10^6\text{ m}}{3 \times 10^8\text{ m/s}} = 0.12\text{ s} = 120\text{ ms} = 120,000\ \mu\text{s}$.
  4. Calculate $a$: $$a = \frac{T_p}{T_t} = \frac{120,000\ \mu\text{s}}{8\ \mu\text{s}} = 15,000$$
  5. Calculate Utilization $\eta$: $$\eta = \frac{1}{1 + 2a} = \frac{1}{1 + 2(15000)} = \frac{1}{30,001} \approx 0.0000333 = \mathbf{0.0033\%}!$$
  6. Effective Throughput: $$\text{Throughput} = \eta \times 1\text{ Gbps} = 0.0000333 \times 1,000,000\text{ kbps} \approx \mathbf{33.3\text{ kbps}}!$$

Shocking Conclusion: Despite purchasing an expensive 1 Gbps link, Stop-and-Wait delivers only 33.3 kbps—over 99.996% of bandwidth is utterly wasted because the sender spends 240 ms doing nothing while waiting for the ACK!

3. The Root Cause: Bandwidth-Delay Product (BDP)

The Bandwidth-Delay Product ($\text{BDP} = B \times \text{RTT}$) represents the volume of bits that can be "in flight" filling the physical cable pipeline. When BDP is high (a "Long-Fat Network" or LFN), Stop-and-Wait is catastrophic because it only keeps a single frame in flight.

9.7 Pipelining Concept & The Sliding Window Paradigm

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Pipelining Concept & Throughput Optimization
Pipelining — First-Principles Definition

Pipelining is a communication technique wherein a sender is permitted to transmit multiple consecutive data frames onto the physical link without waiting for an acknowledgment for each one. The sender keeps multiple unacknowledged frames "in flight" concurrently, completely filling the link's propagation delay pipe.

1. Why Pipelining Exists: Overcoming the Propagation Barrier

In Section 9.6, we proved that Stop-and-Wait collapses link efficiency because the physical wire remains idle while signals travel back and forth across distance $d$. Pipelining solves this by transforming sequential transmission into concurrent, overlapping transmission—hiding propagation latency behind continuous data flow.

Figure 9.7: Stop-and-Wait vs. Pipelined Transmission Timeline
  STOP-AND-WAIT (1 Frame at a time, mostly idle pipe):
  Time:  [Frame 0] .......... (Idle Wire Waiting for ACK) .......... [ACK 1] [Frame 1]
         |<- Tt ->|<---------------------- 2 * Tp ----------------->|<- Tt ->|

  PIPELINED TRANSMISSION (Continuous transmission fills the pipe):
  Time:  [Frame 0][Frame 1][Frame 2][Frame 3][Frame 4] ...
         ACK 0 arrives here ------------^
         Wire is 100% saturated with useful data!

2. Essential Requirements Introduced by Pipelining

Allowing multiple unacknowledged frames in flight dramatically boosts throughput, but introduces major algorithmic requirements:

  • Expanded Sequence Number Space: 1-bit sequence numbers ($0$ and $1$) can no longer distinguish between multiple frames simultaneously on the wire. If $N$ frames can be unacknowledged, we require at least $k$-bit sequence numbers where $2^k > N$.
  • Sender Buffering: The sender must maintain an in-memory buffer storing every unacknowledged frame, because any one of them might be lost in transit and require retransmission.
  • Two Competing Error-Recovery Architectures: What should a protocol do when Frame $k$ is lost while Frames $k+1, k+2$ arrive successfully?
    1. Go-Back-N (GBN): Receiver discards all subsequent out-of-order frames; sender re-sends all $N$ frames starting from $k$.
    2. Selective Repeat (SR): Receiver buffers out-of-order frames; sender re-transmits only the missing Frame $k$.

9.8 Mechanics of Sliding Windows (Pointers & Sequence Space)

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Mechanics, Sequence Numbering & Window Transitions
Sliding Window — First-Principles Definition

A Sliding Window is an abstract memory buffer and sequence-tracking structure maintained by sender and receiver nodes. It imposes an upper bound on the maximum number of unacknowledged data frames that can be in flight simultaneously. As frames are transmitted and acknowledged, the boundaries of the window advance ("slide") along the circular sequence number space.

1. Sender Window ($W_s$) Structure & Pointers

If $n$ bits are allocated for sequence numbers in the frame header, the available sequence numbers span $0$ to $2^n - 1$ using modulo-$2^n$ arithmetic. The sender window is defined by three fundamental boundaries/pointers:

  • $S_f$ (Sequence First / Oldest Unacknowledged): Pointer to the sequence number of the oldest frame that has been transmitted but not yet acknowledged.
  • $S_n$ (Sequence Next to Transmit): Pointer to the sequence number of the next frame ready to be sent.
  • $W_s$ (Window Size): The maximum allowable size of the window ($S_n - S_f < W_s$).
Figure 9.8: Anatomy of the Sender Sliding Window
   Circular Sequence Space: [ 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 ] (Modulo 8, n=3 bits)
   
        Sent & ACKed      Sent, Awaiting ACK     Can Send Immediately    Cannot Send Yet
      ...............   +--------------------+  +--------------------+  .................
     [ 0 | 1 | 2 | 3 ]  |  4   |   5  |   6  |  |   7   |   0   |   1  |  [ 2 | 3 | 4 ... ]
      ...............   +--------------------+  +--------------------+  .................
                          ^                       ^                       ^
                          |                       |                       |
                         Sf (Oldest UnACKed)     Sn (Next to Send)       Sf + Ws (Boundary)
                        |<---------------- Sender Window Ws = 6 ------------------------->|

2. How the Window Transitions ("Slides")

  • Expansion / Shrinking: As the sender transmits a new frame, $S_n$ increments by 1. The window shrinks from the right (fewer remaining frames can be sent).
  • Sliding: When an acknowledgment for frame $k$ arrives, $S_f$ advances forward to $k+1$. The left wall moves rightward, freeing buffer slots and allowing $W_s$ new frames to be transmitted!

3. Receiver Window ($W_r$)

The receiver also maintains a window of size $W_r$ with a pointer $R_n$ pointing to the sequence number of the frame it currently expects:

  • In Go-Back-N: $W_r = 1$. The receiver only accepts the single frame matching $R_n$. Any other frame is discarded!
  • In Selective Repeat: $W_r > 1$ (typically $W_r = W_s$). The receiver accepts and buffers any frame whose sequence number falls within $[R_n, R_n + W_r - 1]$.
⚡ Invariant Law of Sliding Windows

At all times, the number of outstanding unacknowledged frames on the wire is given by:

$$\text{Outstanding Frames} = (S_n - S_f) \pmod{2^n} \le W_s$$

The sender is blocked from transmitting further data whenever $(S_n - S_f) = W_s$.

9.9 Go-Back-N (GBN) ARQ Protocol Working

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Go-Back-N (GBN) Protocol Working & Cumulative ACKs
Go-Back-N (GBN) ARQ — First-Principles Definition

Go-Back-N ARQ is a sliding window protocol where the sender can transmit up to $N$ consecutive frames ($W_s = N > 1$) before needing an acknowledgment, but the receiver possesses a window of size exactly $W_r = 1$. The receiver accepts frames strictly in sequential order and silently discards all out-of-order frames. If a frame is lost, the sender times out and "goes back N", retransmitting all unacknowledged frames starting from the damaged frame.

1. Why GBN Was Designed: Simplicity at the Receiver

In early computing eras, network interface cards (NICs) had minimal RAM buffers (often only a few bytes). GBN was engineered to achieve pipelined throughput while requiring zero buffer memory at the receiver ($W_r = 1$). All buffering complexity is offloaded exclusively to the sender.

2. The Four Cardinal Rules of Go-Back-N

  • 1. Receiver Window Size $W_r = 1$: The receiver only ever searches for one specific sequence number: $R_n$. If frame $R_n$ arrives undamaged, it is accepted and delivered to Layer 3, and $R_n$ increments ($R_n \leftarrow (R_n + 1) \pmod{2^n}$). If any other sequence number arrives (even an undamaged higher frame), it is instantly discarded!
  • 2. Cumulative Acknowledgments: An ACK in GBN is cumulative. An ACK n tells the sender: "I have successfully received and delivered all frames up to and including sequence $n-1$, and I am now awaiting frame $n$." (A single ACK $5$ automatically acknowledges frames $0, 1, 2, 3,$ and $4$!).
  • 3. Single Sender Timer: The sender maintains a single retransmission timer, which is associated with the oldest unacknowledged frame ($S_f$). When an ACK arrives, if there are still outstanding frames, the timer is restarted for the new oldest unacknowledged frame.
  • 4. Timeout Retransmission: If the timer expires, the sender assumes that frame $S_f$ (and possibly all frames transmitted after it) was lost. The sender goes back to $S_f$ and retransmits ALL frames in the range $[S_f, S_n - 1]$!

       SENDER (Ws = 4, Wr = 1)                             RECEIVER (Wr = 1)
         |                                                    |
         | --- Frame 0 -------------------------------------> | (Accepts 0, delivers, Rn=1)

         | --- Frame 2 -------------------------------------> | (Accepts 2, delivers, Rn=3)
         | --- Frame 3 -------------------------------------> | (Accepts 3, delivers, Rn=4)
         |                                                    |
         | <--- ACK 2 --------------------------------------- | (Cumulative ACK for 0 and 1)
   (Window slides!                                            |

   (Window slides again!)                                     |
         v                                                    v

3. Key Advantages of Cumulative ACKs

Cumulative acknowledgments provide extraordinary resilience against ACK loss: if ACK 1, ACK 2, and ACK 3 are destroyed by channel noise, but ACK 4 arrives safely, all four frames are acknowledged simultaneously! No retransmissions occur.

The GBN Retransmission Cascade — First-Principles Definition

When an intermediate frame $k$ is dropped or damaged in Go-Back-N, the receiver's window ($W_r = 1$) refuses to accept any subsequent frames ($k+1, k+2, \dots$), even if they arrive without a single corrupted bit. Upon sender timeout, the sender must retransmit the entire window of $N$ frames—a phenomenon known as the Retransmission Cascade.

9.11 Go-Back-N Window Size Proof: Why $W_s \le 2^n - 1$

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Mathematical Proof of Window Size Bound $W_s \le 2^n - 1$ in GBN
The Go-Back-N Window Inequality Theorem

If an $n$-bit field is allocated for sequence numbers in the frame header, the total sequence number space is $2^n$ ($0, 1, 2, \dots, 2^n - 1$). In Go-Back-N ARQ, the maximum allowable sender window size is strictly bounded by:

W_s \le 2^n - 1 \quad \text{and} \quad W_r = 1

If a sender illegally configures $W_s = 2^n$, catastrophic Wrap-Around Sequence Ambiguity occurs whenever all acknowledgments are lost.

1. Rigorous Proof by Counterexample

Let sequence numbers be represented by $n = 2$ bits. The available sequence numbers are:

$$\text{Sequence Space} = \{0, 1, 2, 3\} \quad (\text{Total } 2^2 = 4 \text{ numbers})$$

Now, let us assume for contradiction that we set $W_s = 2^n = 4$.

Figure 9.11: The Catastrophic Ambiguity When $W_s = 2^n = 4$
   STEP 1: Sender transmits all 4 frames in its window:
           Frame 0, Frame 1, Frame 2, Frame 3.
           
   STEP 2: The receiver receives ALL 4 frames without any corruption!
           - Delivers Frame 0, Frame 1, Frame 2, Frame 3 to Layer 3.
           - Receiver's expected sequence Rn rolls over:
             0 -> 1 -> 2 -> 3 -> wraps back to 0! (Modulo 4 arithmetic)
           - Receiver sends cumulative ACK 0 (meaning "I expect Frame 0 of NEXT batch!").

   STEP 3: DISASTER ON REVERSE CHANNEL!
           All ACKs (or the cumulative ACK 0) are completely destroyed by noise!

   STEP 4: SENDER TIMES OUT!
           Sender never received any ACK. Its timer for Frame 0 expires!
           Sender goes back N and RETRANSMITS the OLD Frame 0!

   STEP 5: RECEIVER RECEIVES RETRANSMITTED FRAME 0!
           Receiver checks its expected pointer: Rn = 0.
           Incoming frame header has sequence number: 0.
           
   💥 FATAL AMBIGUITY:
      The receiver CANNOT TELL whether this incoming Frame 0 is:
      (A) A retransmission of the OLD Frame 0 (which should be DISCARDED), OR
      (B) The BRAND NEW Frame 0 from the next batch (which should be ACCEPTED)!

If the receiver guesses wrong, it either accepts duplicate data (corrupting the user's file) or throws away brand new data (dropping packets silently)!

2. How $W_s = 2^n - 1$ Completely Solves the Ambiguity

Now restrict the window size to $W_s = 2^n - 1 = 4 - 1 = \mathbf{3}$ (Sequence space: $0, 1, 2, 3$):

  1. Sender transmits 3 frames: Frame 0, Frame 1, Frame 2.
  2. Receiver receives all 3 frames safely. $R_n$ advances: $0 \to 1 \to 2 \to \mathbf{3}$.
  3. Receiver returns ACK 3 (expecting Frame 3).
  4. Suppose all ACKs are lost. Sender times out on Frame 0 and retransmits Frame 0.
  5. Receiver inspects incoming frame: It receives Seq 0, but its pointer $R_n$ is waiting for Seq 3!
  6. Because $0 \ne 3$, the receiver unambiguously knows that Frame 0 is an OLD duplicate! It safely discards the duplicate and resends ACK 3!

Thus, no ambiguity can ever occur when $W_s \le 2^n - 1$.

⚡ Universal Mathematical Rule for Window Bounds

For any sliding window protocol to avoid wrap-around ambiguity under arbitrary ACK loss, the sum of sender and receiver window sizes must not exceed the sequence number space:

$$W_s + W_r \le 2^n$$

Since in Go-Back-N, $W_r = 1$:

$$W_s + 1 \le 2^n \implies \mathbf{W_s \le 2^n - 1}$$

9.12 Selective Repeat (SR) ARQ Protocol Working

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Selective Repeat (SR) ARQ Protocol & Receiver Buffering
Selective Repeat (SR) ARQ — First-Principles Definition

Selective Repeat ARQ is an advanced sliding window protocol designed to maximize link efficiency by eliminating the wasteful retransmission cascade of Go-Back-N. The receiver allocates a window of buffer memory ($W_r > 1$, typically $W_r = W_s$) to accept and store out-of-order frames. When an error occurs, the sender retransmits ONLY the specific missing or corrupted frame, while all other successfully received frames are preserved.

1. Why Selective Repeat Was Developed

On satellite links, high-speed fiber-optic lines, or wireless channels with significant packet loss, retransmitting $N$ frames for every single bit flip severely degrades throughput. Selective Repeat ensures that every frame that successfully traverses the wire is kept, minimizing retransmission overhead to the theoretical lower bound.

2. The Four Pillars of Selective Repeat

  • 1. Receiver Window Size $W_r > 1$: The receiver maintains a buffer window of size $W_r = W_s$. It accepts any frame whose sequence number falls within the window $[R_n, R_n + W_r - 1]$, regardless of whether it arrives in order or out of order!
  • 2. Individual / Selective Acknowledgments (SACKs): Each frame is acknowledged individually. An ACK k strictly confirms receipt of Frame $k$. (In modern protocols, Negative ACKs (NAKs) can also be used to explicitly request immediate retransmission of a missing frame).
  • 3. Independent Sender Timers: Because frames can be acknowledged in any arbitrary order, the sender maintains an independent countdown timer for each individual frame in flight.
  • 4. In-Order Delivery to Layer 3: While the receiver accepts out-of-order frames into its buffer, it delivers packets to the higher network layer strictly in sequence. Out-of-order frames are held in the buffer until the missing preceding frame arrives, at which point the entire consecutive block is pushed to Layer 3 and the receiver window slides forward.

      ......................     +-------+      +---------------------------------+

                               Rn (Left Wall of Receiver Window Wr = 4)

3. Hardware Trade-Off: Efficiency vs. Complexity

While Selective Repeat achieves optimal transmission efficiency, it imposes significantly higher hardware complexity:

  • Sender: Must track $N$ independent timers and maintain a complex lookup queue.
  • Receiver: Must provide fast sorting buffers and complex reassembly logic before delivering packets to Layer 3.

9.14 Selective Repeat Window Size Proof: Why $W_s \le 2^{n-1}$

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Mathematical Proof of Window Bound $W_s \le 2^{n-1}$ in Selective Repeat
The Selective Repeat Window Size Inequality Theorem

If $n$ bits are allocated for sequence numbers, the total sequence number space is $2^n$ ($0, 1, 2, \dots, 2^n - 1$). In Selective Repeat ARQ, the maximum allowable sender and receiver window sizes must satisfy:

W_s + W_r \le 2^n

Since symmetrical buffer implementation requires $W_s = W_r$:

2W_s \le 2^n \implies \mathbf{W_s \le 2^{n-1} \quad \text{and} \quad W_r \le 2^{n-1}}

1. Rigorous Proof by Counterexample: The Failure When $W_s > 2^{n-1}$

Let $n = 2$ bits $\implies 2^2 = 4$ sequence numbers: $\{0, 1, 2, 3\}$.
Suppose we illegally choose a window size larger than $2^{n-1}$, say $W_s = W_r = 3$ (since $3 > 2^{2-1} = 2$).

9.15 Comprehensive Protocol Comparison (SW vs GBN vs SR)

🎓 Uni Required Prescribed syllabus topic: Data Link Protocols: Comprehensive Comparison of Stop-and-Wait, GBN, and Selective Repeat
Protocol Comparison — Core Engineering Trade-offs

Data link layer protocol selection represents a fundamental trade-off between channel utilization efficiency on one hand and endpoint hardware/memory complexity on the other. Stop-and-Wait maximizes simplicity at the cost of catastrophic underutilization; Go-Back-N provides high throughput with simple receivers; Selective Repeat achieves theoretical maximum throughput under high error rates at the expense of substantial receiver buffer complexity.

Decision Framework: Which Protocol to Deploy?

  • Deploy Stop-and-Wait when: The physical link has near-zero propagation delay ($a \approx 0$, e.g., adjacent chips on a circuit board or short USB cables), or endpoints have virtually zero RAM.
  • Deploy Go-Back-N when: The transmission channel has a high Bandwidth-Delay Product (BDP) but a very low bit error rate (BER) (e.g., modern fiber optic cables), and receiver memory must be kept minimal.
  • Deploy Selective Repeat when: The channel exhibits both high latency and high error rates (e.g., satellite communications, noisy military wireless, cellular links), where retransmitting undamaged frames is unacceptable.

9.16 Throughput, Bandwidth-Delay Product & Efficiency Calculations

🎓 Uni Required Prescribed syllabus topic: Sliding Window Protocols: Mathematical Calculations of Efficiency, Throughput & Window Sizing
Sliding Window Efficiency Formula — First Principles

In a sliding window protocol with sender window size $N$, the sender can transmit up to $N$ frames continuously within one round-trip cycle time ($T_t + 2T_p$). The theoretical channel utilization ($\eta$) under error-free conditions is:

\eta = \frac{N \times T_t}{T_t + 2T_p} = \frac{N}{1 + 2a} \quad \text{where } a = \frac{T_p}{T_t}

Since utilization cannot exceed 100% ($\eta \le 1.0$):

\eta = \min\left(1.0, \; \frac{N}{1 + 2a}\right)

1. The Condition for 100% Maximum Link Utilization

To achieve 100% efficiency ($\eta = 1.0$), the window size $N$ must be large enough to keep transmitting continuously until the acknowledgment for the very first frame returns:

Optimal Window Size Theorem
N \ge 1 + 2a = 1 + \frac{2T_p}{T_t} = 1 + \frac{2 \times d \times B}{v \times L}
• If $N < 1 + 2a$: Link is underutilized ($\eta = \frac{N}{1 + 2a} < 1$).
• If $N \ge 1 + 2a$: Link achieves 100% capacity ($\eta = 1.0$). Further increasing $N$ does not increase throughput.

2. Worked Numerical Example (High-Yield GATE & University Problem)

📝 Worked Numerical 9.2 — Optimal Window and Sequence Bits

Problem: A 100 Mbps point-to-point fiber-optic link connects two routers separated by $2000\text{ km}$. The signal propagation velocity in fiber is $2 \times 10^8\text{ m/s}$. Frame size is $2000\text{ bytes}$. Find:

  1. Propagation delay $T_p$ and Transmission delay $T_t$.
  2. Parameter $a$.
  3. Efficiency under Stop-and-Wait.
  4. Minimum sender window size $N$ required to achieve 100% link utilization.
  5. Minimum sequence number bits ($n$) required under Go-Back-N and Selective Repeat.

Solution:

  1. Delays: $$T_p = \frac{d}{v} = \frac{2000 \times 10^3\text{ m}}{2 \times 10^8\text{ m/s}} = 0.01\text{ s} = 10\text{ ms}$$ $$L = 2000 \times 8 = 16,000\text{ bits}$$ $$T_t = \frac{L}{B} = \frac{16,000\text{ bits}}{100 \times 10^6\text{ bps}} = 0.00016\text{ s} = 0.16\text{ ms}$$
  2. Parameter $a$: $$a = \frac{T_p}{T_t} = \frac{10\text{ ms}}{0.16\text{ ms}} = 62.5$$
  3. Stop-and-Wait Efficiency: $$\eta_{\text{SW}} = \frac{1}{1 + 2a} = \frac{1}{1 + 2(62.5)} = \frac{1}{126} \approx 0.00794 = \mathbf{0.794\%}!$$
  4. Optimal Window Size $N$: $$N \ge 1 + 2a = 1 + 125 = \mathbf{126\text{ frames}}$$
  5. Sequence Bits $n$:

    • For Go-Back-N: $$W_s \le 2^n - 1 \implies 2^n - 1 \ge 126 \implies 2^n \ge 127$$ Since $2^6 = 64$ and $2^7 = 128 \implies \mathbf{n = 7\text{ bits}}$.

    • For Selective Repeat: $$W_s \le 2^{n-1} \implies 2^{n-1} \ge 126$$ Since $2^6 = 64$ and $2^7 = 128 \implies n - 1 = 7 \implies \mathbf{n = 8\text{ bits}}$.

3. Efficiency Under Error-Prone Channels (Packet Loss Rate $P$)

When each frame has an independent drop probability $P$:

  • Stop-and-Wait with Loss: $\eta = \frac{1 - P}{1 + 2a}$
  • Selective Repeat with Loss: $\eta \approx (1 - P) \times \min\left(1.0, \; \frac{N}{1 + 2a}\right)$ (Only lost frames retransmitted)
  • Go-Back-N with Loss: $\eta \approx \frac{1 - P}{1 + (N - 1)P} \times \min\left(1.0, \; \frac{N}{1 + 2a}\right)$ (Because each lost frame wastes $N$ transmissions!)

9.17 Bidirectional Communication, Piggybacking & Delayed ACKs

🎓 Uni Required Prescribed syllabus topic: Data Link Protocols: Bidirectional Transmission, Piggybacking & Delayed ACKs
Piggybacking — First-Principles Definition

Piggybacking is a protocol optimization technique used in full-duplex, bidirectional communication channels where an outgoing acknowledgment (ACK) is temporarily delayed and embedded (piggybacked) directly into the header of the next outgoing data frame traveling in the reverse direction.

1. Why Piggybacking Exists: Eliminating Control Overhead

In standard half-duplex models, sending an ACK requires transmitting a standalone control frame consisting of preamble, start flag, address, sequence number, CRC, and stop flag (often 20 to 60 bytes of overhead) just to convey 1 or 2 bytes of acknowledgment information. When both stations are actively exchanging data (e.g., interactive terminal sessions or video streaming), standalone ACKs waste substantial channel bandwidth.

2. The Dilemma: How Long Should the Receiver Wait?

Piggybacking introduces a critical engineering dilemma:

⚠️ The ACK Starvation Problem & The Delayed ACK Timer

What happens if the receiver receives a data frame, but its local network layer has no outgoing data to send in the reverse direction? If the receiver waits indefinitely for reverse data, the sender's retransmission timer will expire, triggering unnecessary duplicate retransmissions!

Solution: The Delayed ACK Timer:

  • When an incoming frame arrives, the receiver starts a short ACK Countdown Timer (typically 50 ms to 200 ms).
  • Case 1 (Reverse data ready): If a reverse data packet is queued before the ACK timer expires, the ACK is piggybacked on that frame, and the timer is canceled.
  • Case 2 (Timer expires): If the timer expires before any reverse data is queued, the receiver immediately transmits a standalone ACK frame without data.

3. Benefits and Limitations

  • Advantages: Massive reduction in packet header overhead; saves transmission energy; cuts interrupt processing loads on networking cards.
  • Limitations: Adds complexity to protocol state machines; can cause jitter if ACK timer is poorly tuned; excessive delay risks triggering sender timeouts.

Chapter 9 Core Synthesis

Data link protocols evolve from elementary flow-control mechanisms (Utopia, Stop-and-Wait) to robust error-recovery systems (Stop-and-Wait ARQ) and finally to high-throughput pipelined architectures (Go-Back-N and Selective Repeat). Top 5 High-Yield Examination Traps & Pitfalls

⚠️ Trap 1: Off-by-One in GBN Window Size ($2^n - 1$ vs $2^n$)

Questions frequently state: "Sequence number is 4 bits. What is maximum window size in GBN?"
Wrong Answer: $2^4 = 16$.
Correct Answer: $2^4 - 1 = \mathbf{15}$. (If $W_s = 16$, duplicate frames cannot be distinguished upon total ACK loss).

⚠️ Trap 2: Sequence Bits for Selective Repeat ($2^{n-1}$ vs $2^n - 1$)

Questions state: "A link requires window size $N = 8$. How many sequence bits are required for SR?"
Wrong Answer: $W_s \le 2^n - 1 \implies 8 \le 2^4 - 1 \implies n = 4$.
Correct Answer: In Selective Repeat, $W_s \le 2^{n-1} \implies 8 \le 2^{n-1} \implies n - 1 = 3 \implies \mathbf{n = 4\text{ bits}}$. (Be extremely careful not to confuse the GBN formula with the SR formula!).

⚠️ Trap 3: Unit Conversion Errors in Transmission Delay

Watch out for Bytes vs. Bits and Megabytes vs. Megabits! If frame size is given as 1 KB and bandwidth is 10 Mbps:
$L = 1000 \times 8 = 8000\text{ bits}$ (or $1024 \times 8 = 8192\text{ bits}$ depending on convention). If you forget to multiply by 8, your $T_t$ will be off by a factor of 8, invalidating all subsequent answers!

⚠️ Trap 4: Round-Trip Time Includes $2T_p$, NOT $T_p$

Total cycle time is $T_t + 2T_p$, because the data frame travels forward ($T_p$) and the ACK frame travels backward ($T_p$). Writing $T_t + T_p$ is an instant 50% deduction in university exams.

⚠️ Trap 5: Cumulative ACK Mechanics in GBN

In GBN, an ACK acknowledges all prior frames up to $n-1$. If an exam question says "Frames 0, 1, 2, 3 were sent. ACK 1 and ACK 2 are lost, but ACK 4 arrives safely. How many frames are retransmitted?"
Answer: ZERO! Because ACK 4 cumulatively acknowledges Frames 0, 1, 2, and 3, the loss of intermediate ACKs has zero adverse effect!
