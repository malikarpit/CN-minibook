2.1 Types of Networks

🎓 Uni Required Required for syllabus topic: Network types (PAN, LAN, MAN, WAN, WLAN)

Networks are classified primarily by their geographic scope — the physical area they cover. Each type serves different purposes and uses different technologies.

PAN — Personal Area Network

PAN (Personal Area Network)
A network that connects devices within a very small range — typically around a single person (within ~10 meters). Used for personal device interconnection.
  • Range: ~1–10 meters
  • Speed: Low to moderate (1–3 Mbps typical for Bluetooth)
  • Examples: Bluetooth headset ↔ phone, smartwatch ↔ phone, wireless keyboard ↔ laptop, USB connection between phone and PC
  • Technologies: Bluetooth (IEEE 802.15.1), Zigbee (802.15.4), USB, NFC
  • Ownership: Individual

LAN — Local Area Network

LAN (Local Area Network)
A network that connects devices within a limited geographic area — a single building, office, school campus, or home. LANs are the most common type of network.
  • Range: ~10 meters to 1 km (single building or campus)
  • Speed: High (100 Mbps to 10 Gbps and beyond)
  • Examples: Office network, university computer lab, home Wi-Fi network
  • Technologies: Ethernet (IEEE 802.3), Wi-Fi (802.11)
  • Ownership: Usually private (owned by a single organization)
  • Key characteristic: Low latency, high throughput, typically shared medium or switched

MAN — Metropolitan Area Network

MAN (Metropolitan Area Network)
A network spanning a city or large campus — larger than a LAN but smaller than a WAN. Connects multiple LANs within a city.
  • Range: ~5–50 km (a city or metropolitan area)
  • Speed: Moderate to high (10 Mbps to 1 Gbps)
  • Examples: Cable TV network across a city, university with multiple campuses linked via fiber, city-wide public Wi-Fi
  • Technologies: Fiber optics, WiMAX (IEEE 802.16), Metro Ethernet
  • Ownership: Can be private or operated by service providers

WAN — Wide Area Network

WAN (Wide Area Network)
A network that spans large geographic areas — countries, continents, or the entire globe. WANs connect multiple LANs and MANs across vast distances.
  • Range: Hundreds to thousands of km (country, continent, global)
  • Speed: Variable (lower than LAN due to distance; can be high with fiber backbone)
  • Examples: The Internet (the largest WAN), a multinational company's global network, BSNL's network connecting Indian cities
  • Technologies: Leased lines, MPLS, satellite links, submarine fiber cables
  • Ownership: Often operated by telecom companies (ISPs); enterprises lease connections
  • Key characteristic: Higher latency than LAN, uses routers and public/leased infrastructure

WLAN — Wireless Local Area Network

WLAN (Wireless LAN)
A LAN that uses wireless communication (radio waves) instead of cables. Follows the IEEE 802.11 standard (commonly called Wi-Fi).
  • Range: ~30–100 meters indoors (depends on walls, interference)
  • Speed: Moderate to high (Wi-Fi 6: up to 9.6 Gbps theoretical)
  • Examples: Home Wi-Fi, coffee shop hotspot, airport Wi-Fi
  • Key distinction from LAN: Same scope, but uses radio instead of cables. A WLAN is a type of LAN.

💡
MCQ Memory Aid: Think of network types by range: PAN (person) → LAN (building) → MAN (city) → WAN (world). The acronyms spell P-L-M-W in order of increasing range.
⚠️
Common MCQ Trap: "The Internet is a LAN." — FALSE. The Internet is a WAN — in fact, it's the largest WAN on Earth. Also: "A WLAN is not a LAN." — FALSE. A WLAN is a type of LAN (just wireless). Don't confuse scope with medium.

2.3 Client-Server vs Peer-to-Peer

🎓 Uni Required Required for syllabus topic: Network models (Client-Server vs Peer-to-Peer Models)

Client-Server Architecture

Client-Server Model
A network architecture where a dedicated server provides services (files, web pages, databases) and clients request and consume those services. The server is always-on; clients connect as needed.
Client-Server Architecture

       ┌────────┐        Request         ┌──────────┐
       │ Client │ ────────────────────▶  │          │
       │   A    │                        │  SERVER  │
       │        │ ◀────────────────────  │ (always  │
       └────────┘        Response        │   on)    │
                                         │          │
       ┌────────┐        Request         │ stores   │
       │ Client │ ────────────────────▶  │ data,    │
       │   B    │                        │ serves   │
       │        │ ◀────────────────────  │ requests │
       └────────┘        Response        │          │
                                         │          │
       ┌────────┐        Request         │          │
       │ Client │ ────────────────────▶  │          │
       │   C    │                        │          │
       │        │ ◀────────────────────  │          │
       └────────┘        Response        └──────────┘

Peer-to-Peer (P2P) Architecture

Peer-to-Peer (P2P) Model
A network architecture where every device (peer) has equal status — each can act as both client and server simultaneously. There is no dedicated central server. Resources are shared directly between peers.

       │ Peer A │                   │ Peer B │

       │+server)│                   │+server)│
       └────────┘                   └────────┘
            ▲                           ▲
            │                           │
            ▼                           ▼
       ┌────────┐ ◀──────────────▶ ┌────────┐
       │ Peer C │                   │ Peer D │
       │(client │                   │(client │
       │+server)│                   │+server)│
       └────────┘                   └────────┘

AspectClient-ServerPeer-to-Peer

CostHigher (server hardware)Lower (no dedicated server)
ScalabilityLimited by server capacityScales naturally (each peer adds resources)

Centralized vs Distributed Networking

Centralized networking places all control and data at a central point (one server, one switch). It's simple to manage but creates a single point of failure. If the center goes down, everything stops.

Distributed networking spreads control, data, and processing across multiple nodes. It's more resilient (no single point of failure) but more complex to manage. P2P is inherently distributed; client-server is centralized.

⚠️
MCQ Trap: "In P2P, there are no servers." — Misleading. In P2P, every peer can act as a server. There's no dedicated server, but the server role exists on every peer. Read the question carefully: "no dedicated server" is correct; "no server functionality" is incorrect.

2.4 Network Topologies — Overview 🎓 Uni: Topologies

🎓 Uni Required Required for syllabus topic: Network topologies (Physical vs Logical Topologies Overview)
Network Topology
The physical or logical arrangement of nodes and links in a network. It defines how devices are interconnected and how data flows between them.

Physical vs Logical Topology

TypeWhat It DescribesExample
Physical TopologyThe actual physical layout — how cables and devices are physically arrangedCables running from each PC to a central switch in a star pattern
Logical TopologyHow data actually flows through the network, regardless of physical layoutToken Ring: physically wired as a star (to a hub), but data flows logically in a ring

Key insight: A network can have different physical and logical topologies. For example, a Token Ring network may be physically wired as a star (all devices connect to a central hub/MAU), but logically the data travels in a ring pattern.

Why Does Topology Matter?

  • Cost — How much cabling and hardware is needed?
  • Performance — How efficiently does data flow?
  • Fault tolerance — What happens when a cable or device fails?
  • Scalability — How easy is it to add new devices?
  • Maintenance — How easy is it to identify and fix problems?

We will now examine each topology in detail: Bus, Star, Ring, Mesh, Tree, Hybrid, and Point-to-Point/Multipoint.

2.5 Bus Topology

🎓 Uni Required Required for syllabus topic: Network topologies (Bus Topology)
Bus Topology
A network topology in which all devices are connected to a single central cable called the backbone (or bus). Data sent by any device travels along the entire bus in both directions, and every device receives the signal, but only the intended recipient processes it.
Bus Topology Diagram

  Terminator                                           Terminator
     ║                                                      ║
     ╠══════╦══════╦══════╦══════╦══════╦══════╦════════════╣
            ║      ║      ║      ║      ║      ║
           [A]    [B]    [C]    [D]    [E]    [F]

  ═══ = Backbone cable (shared bus)
  [X] = Network devices (computers/nodes)
  ║   = Drop cables / T-connectors

How It Works

  1. When device A wants to send data to device D, it places the data on the bus.
  2. The signal travels in both directions along the bus.
  3. All devices on the bus receive the signal (broadcast).
  4. Each device checks the destination address in the frame header.
  5. Only device D (matching the destination address) accepts and processes the data.
  6. All other devices ignore the data.
  7. Terminators at both ends absorb signals, preventing them from bouncing back (reflection).
Advantages ✅Disadvantages ❌
Simple to install and extendBackbone failure = entire network down
Less cabling than star or meshDifficult to troubleshoot (which part of bus failed?)
Low cost for small networksPerformance degrades as more devices are added (collisions increase)
Works well for temporary/small setupsLimited cable length and number of devices
Security is poor (all devices see all traffic)
If terminator is missing, signal reflection disrupts the network

Failure behavior: If the backbone cable is cut at any point, the network is split into two segments that cannot communicate — the entire network fails. If a single device fails, the rest of the network continues to work (unless the failure shorts the bus).

Applications: Early Ethernet networks (10Base2, 10Base5), small temporary networks. Largely obsolete today — replaced by star topology with switches.

⚠️
MCQ Trap: "In bus topology, if one device fails, the whole network fails." — Not necessarily true. If a device fails, the network usually continues. If the backbone cable fails, then the network goes down. The single point of failure is the cable, not any individual device.

2.6 Star Topology

🎓 Uni Required Required for syllabus topic: Network topologies (Star Topology)
Star Topology
A network topology where every device is connected to a central hub or switch via a dedicated point-to-point link. All communication passes through the central device.
Star Topology Diagram

            [A]          [B]
              \          /
               \        /
                \      /
            ┌────────────┐
            │   HUB /    │
            │  SWITCH    │
            └────────────┘
                /      \
               /        \
              /          \
            [C]          [D]
                  |
                 [E]

How It Works

  1. Each device has its own dedicated cable to the central hub/switch.
  2. When device A sends data to device D, it goes to the central device first.
  3. If using a hub: the hub broadcasts to all ports (like a bus internally).
  4. If using a switch: the switch forwards only to device D's port (intelligent forwarding).
Advantages ✅Disadvantages ❌
Easy to install, configure, and manageCentral device failure = entire network down
Easy to troubleshoot (isolate faulty cable/device)More cabling required than bus
One device/cable failure doesn't affect othersDependent on central device capacity
Easy to add/remove devices without disruptionCost of central hub/switch
Good performance (especially with switches)Limited by number of ports on central device

Failure behavior: If one link (cable) fails, only that device is disconnected. All other devices continue to function. However, if the central hub/switch fails, the entire network goes down — this is the single point of failure.

Applications: Modern Ethernet LANs (most office/home networks today), virtually all switched networks. This is the most common topology in use today.

💡
Hub vs Switch in Star: A star with a hub is internally like a bus (all devices share bandwidth, collisions possible). A star with a switch gives each device dedicated bandwidth and eliminates collisions. The topology is the same (star), but the behavior is very different.

2.7 Ring Topology

🎓 Uni Required Required for syllabus topic: Network topologies (Ring Topology)
Ring Topology
A network topology where each device is connected to exactly two neighboring devices, forming a closed circular path. Data travels around the ring in one direction (unidirectional) or both directions (dual ring).
Ring Topology Diagram (Unidirectional)

              [A] ──────▶ [B]
              ▲               │
              │               ▼
             [E]             [C]
              ▲               │
              │               ▼
              [D] ◀────── [C]

    Direction of data flow: A → B → C → D → E → A
    (Each device regenerates and forwards the signal)

How It Works

  1. Data travels around the ring in one direction (unidirectional ring) or both (bidirectional/dual ring).
  2. Each device acts as a repeater: it receives the signal, regenerates it, and passes it to the next device.
  3. When device A sends data to device D, the data passes through B, then C, until it reaches D.
  4. Device D copies the data, and the frame continues around the ring back to A.
  5. The sender (A) removes the frame from the ring.

Token Passing (Token Ring Protocol — IEEE 802.5)

A common protocol used with ring topology is Token Passing:

  • A special small frame called a token circulates around the ring.
  • A device can only transmit data when it captures the token.
  • After transmitting, the device releases the token for the next device.
  • This prevents collisions (only one device transmits at a time).

Single Ring vs Dual Ring

FeatureSingle RingDual Ring
Data pathsOne (unidirectional)Two (opposite directions)
If a link failsEntire ring breaksRing wraps around — uses backup ring to bypass failure
CostLowerHigher (double the cable)
ExampleBasic Token RingFDDI (Fiber Distributed Data Interface)
Advantages ✅Disadvantages ❌
Equal access (no collisions with token passing)One device/link failure can break the ring (single ring)
Performs well under heavy load (deterministic)Difficult to add/remove devices (must break ring)
No collision (with token passing)Troubleshooting is difficult
Signal is regenerated at each node → longer distancesData must pass through every intermediate node → latency
Predictable maximum delaySlower than star for light traffic

Failure behavior: In a single ring, if any single link or device fails, the entire ring breaks. In a dual ring (like FDDI), the ring can "wrap" around the failure point, maintaining connectivity.

Applications: Token Ring (IBM, mostly obsolete), FDDI (campus backbones, mostly obsolete), SONET/SDH (telecom rings, still used).

⚠️
MCQ Trap: "Ring topology requires token passing." — FALSE. Ring is a topology (physical arrangement). Token passing is a protocol (access control mechanism). A ring topology could theoretically use other access methods. However, in practice, token passing is strongly associated with ring topology. Read the question carefully.

2.8 Mesh Topology

🎓 Uni Required Required for syllabus topic: Network topologies (Mesh Topology & Link Calculation n(n-1)/2)
Mesh Topology
A network topology where every device has a dedicated point-to-point link to every other device. In a full mesh, every pair of devices is directly connected. In a partial mesh, some devices are directly connected while others connect through intermediaries.
Full Mesh Topology (4 nodes)

            [A] ─────────────── [B]
            │ \               / │
            │   \           /   │
            │     \       /     │
            │       \   /       │
            │         X         │
            │       /   \       │
            │     /       \     │
            │   /           \   │
            │ /               \ │
            [D] ─────────────── [C]

    Every device is connected to every other device.
    4 nodes → 6 links (full mesh)

Formula: Number of Links in a Full Mesh

Full Mesh Link Count
Links = n(n − 1) / 2
where n = number of nodes

Also: each node needs (n − 1) I/O ports
⚡ Competitive Exam

Worked Examples

Nodes (n)Links = n(n-1)/2Ports per node = n-1
44×3/2 = 63
55×4/2 = 104
1010×9/2 = 459
2020×19/2 = 19019
100100×99/2 = 4,95099

Notice how the number of links grows quadratically — this is why full mesh is impractical for large networks.

Full Mesh vs Partial Mesh

FeatureFull MeshPartial Mesh
ConnectionsEvery device connected to every otherSome direct connections, some through intermediate nodes
RedundancyMaximumModerate
CostVery highModerate
Use caseCritical backbone routersMost real-world networks
Advantages ✅Disadvantages ❌
Maximum fault tolerance (multiple paths available)Extremely expensive (lots of cables and ports)
No single point of failureComplex installation and maintenance
High performance (dedicated links, no sharing)Impractical for large numbers of nodes
Privacy (dedicated links → no eavesdropping on shared medium)Quadratic growth in links: n(n-1)/2
Easy fault identificationEach device needs (n-1) ports

Failure behavior: Excellent. If one link fails, data can be rerouted through alternate paths. Multiple links would have to fail simultaneously to disconnect a device. This is the most fault-tolerant topology.

Applications: Internet backbone (core routers), WAN connections between major cities, military networks where reliability is critical. The Internet's core is essentially a partial mesh.

⚠️
MCQ Trap: "A network with 5 devices needs 10 links for full mesh." — You need to verify: 5×4/2 = 10. ✅ Correct. But "A network with 5 devices needs 5 links for full mesh" — ❌ That's wrong (5 links would be a ring).

2.9 Tree Topology

🎓 Uni Required Required for syllabus topic: Network topologies (Tree / Hierarchical Topology)
Tree Topology
A hierarchical topology that combines characteristics of star and bus. Devices are arranged in a hierarchy with a root node at the top, and branches of star networks connected via a backbone. Also called a hierarchical topology.
Tree Topology Diagram

                    [Root Switch]
                    /            \
                   /              \
          [Switch 1]            [Switch 2]
           /  |  \               /  |  \
          /   |   \             /   |   \
        [A]  [B]  [C]        [D]  [E]  [F]

    Root level:   Central backbone switch/router
    Level 1:      Department switches
    Level 2:      End devices (computers)

How It Works

  • Multiple star networks are connected via a backbone (bus).
  • Data flows up the hierarchy to the backbone, then down to the destination branch.
  • The root node controls the entire network.
Advantages ✅Disadvantages ❌
Natural hierarchy — matches organizational structureRoot/backbone failure = large portion of network down
Easy to add new branches (star groups)More cabling than bus or star alone
Isolating faults is easier by branchIf a branch switch fails, that branch is disconnected
Scales better than flat bus/starComplex to configure
Good for large campuses with departmentsDependent on backbone cable

Failure behavior: If a branch switch fails, only that branch is affected. If the root or backbone fails, large portions (or all) of the network go down.

Applications: Large campus networks, corporate networks with departments on different floors, cable TV distribution.

2.10 Hybrid & Point-to-Point/Multipoint

🎓 Uni Required Required for syllabus topic: Network topologies (Hybrid & Point-to-Point / Multipoint)

Hybrid Topology

Hybrid Topology
A topology that combines two or more different topologies to form a larger network. For example, a star-bus hybrid connects multiple star networks via a bus backbone (which is essentially a tree topology). A star-ring hybrid connects star groups in a ring pattern.
  • Advantages: Flexible, scalable, inherits strengths of component topologies, can be designed to meet specific needs.
  • Disadvantages: Complex to design and manage, expensive, troubleshooting can be challenging.
  • Real-world usage: Most large-scale real networks are hybrids. A university might use star topology within each building and mesh/tree connectivity between buildings.

Point-to-Point Link

Point-to-Point
A dedicated link between exactly two devices. The entire capacity of the link is reserved for those two devices. Examples: a leased line between two offices, a USB cable between computer and printer, a direct fiber link between two routers.

Point-to-Multipoint (Multipoint / Multidrop)

Point-to-Multipoint (Multipoint)
A link shared by more than two devices. Multiple devices share the same communication channel. Examples: a bus topology cable, a Wi-Fi access point broadcasting to multiple devices, a satellite broadcasting to ground receivers.
FeaturePoint-to-PointMultipoint
Devices per linkExactly 23 or more
BandwidthDedicated (full capacity)Shared among devices
ExamplesLeased line, USB, direct fiberBus cable, Wi-Fi, satellite
PrivacyHigh (only 2 devices on the link)Lower (all devices see all traffic)
CostHigher per linkLower (shared medium)
💡
Key insight: "Point-to-point" refers to the link type, not a topology per se. Star topology uses point-to-point links (each device has a dedicated link to the hub). Mesh topology also uses point-to-point links (every pair has a dedicated link). Bus topology uses a multipoint link.

Quick Decision Guide for MCQs

💡
"How to recognize a topology in an MCQ":
  • Question mentions "backbone cable" or "terminator" → Bus
  • Question mentions "central hub" or "central switch" → Star
  • Question mentions "token passing" or "circular path" → Ring
  • Question mentions "dedicated link to every other device" or asks about n(n-1)/2 → Mesh
  • Question mentions "hierarchical" or "root node" or "star+bus combination" → Tree
  • Question mentions "combination of topologies" → Hybrid

Section Recap

📌
Key takeaways from Chapter 2:
  • Networks by scope: PAN → LAN → MAN → WAN (increasing range)
  • Internet (public) ⊃ Extranet (partners) ⊃ Intranet (internal only)
  • Client-server: centralized, one dedicated server; P2P: distributed, all peers equal
  • Physical topology ≠ logical topology (they can differ)
  • Bus: shared backbone, cheap but fragile; obsolete
  • Star: central hub/switch, most common today, easy to troubleshoot
  • Ring: circular path, token passing, deterministic but fragile (single ring)
  • Mesh: n(n-1)/2 links, maximum fault tolerance, very expensive
  • Tree: hierarchical star+bus, good for departments/campuses
  • Real networks are usually hybrid combinations
